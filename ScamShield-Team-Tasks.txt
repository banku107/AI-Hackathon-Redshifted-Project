=====================================================================
  HOW THE PROJECT WORKS (in simple words)
=====================================================================

  Think of ScamShield as a FRIENDLY DETECTIVE THAT LIVES IN YOUR PHONE.
  Grandma shows it a message she's worried about, and it checks the
  message for her.

  STEP 1 - GRANDMA SHOWS IT THE MESSAGE
    She opens the website on her phone and does one of these:
      - pastes the text message
      - uploads a screenshot
      - uploads a video
    Then she taps "Check it".

  STEP 2 - THE AI MAKES A PLAN
    The message goes to Claude (the AI). Claude doesn't just guess. It
    first writes a short plan, like:
      1. Check the link
      2. Check the phone number
      3. Look for scam tricks
    Grandma sees this plan on her screen, and each step ticks off as
    it's done.

  STEP 3 - THE AI INVESTIGATES WITH TOOLS
    Claude has tools, which are small helpers it can use:
      - Where does this link really go? (Short links often hide a
        different website.)
      - How old is this website? (A site made 2 days ago is a big
        warning sign.)
      - Is it copying a real company? (Like "paypa1.com" pretending to
        be PayPal.)
      - Is it on a known scam list?
      - Web search: has anyone reported this phone number? What is the
        company's REAL phone number?
    It also spots common scam tricks: rushing you, asking for gift
    cards, or saying "don't tell anyone".

  STEP 4 - IT DOUBLE-CHECKS ITSELF
    Before answering, Claude checks that every reason it gives comes
    from real evidence it found. If it's not sure, it says so instead
    of scaring her for nothing.

  STEP 5 - IT GIVES A CLEAR ANSWER
    A big colored card appears, in Grandma's language:
      RED    = SCAM
      YELLOW = BE CAREFUL
      GREEN  = LOOKS REAL
    The card also shows:
      - 2-3 simple reasons ("This website was made 2 days ago and
        pretends to be USPS.")
      - what to do now ("Don't reply. Call your grandson on his usual
        number.")
      - the company's REAL phone number, never the one in the message
      - a "Read aloud" button

  STEP 6 - IT TAKES ACTION
    - Warns family: if it's a scam and money is involved, it sends an
      alert to a family member's phone.
    - Damage control: if Grandma says "I already sent a gift card", it
      gives a checklist (call the gift card company, freeze the card)
      and a ready-made report for the authorities.

  VIDEOS WORK A LITTLE DIFFERENTLY
    The AI can't watch a video directly, so:
      1. The phone takes about 10 still pictures from the video.
      2. The app runs 3 checks: a hidden "made by AI" label, the file
         details, and an AI-video detector service.
      3. Claude looks at the pictures for AI mistakes (extra fingers,
         lips that don't match the words).
      4. Claude checks what the video CLAIMS. For example, did this
         person really announce a crypto giveaway?
    Then it gives TWO answers: "Is it made by AI?" and "Is it a scam?".
    A real video can still be a scam, and an AI video isn't always a
    scam.

  HOW THE 4 TEAM MEMBERS' PARTS FIT TOGETHER

     Grandma's phone    ---->    The brain    ---->    The tools
     (Person 3:              (Person 1:            (Person 2:
      screens)                Claude)               checks)
          ^                      |
          |                      |
          +---- live updates + answer card ----+

     Person 4: tests it with examples, scores how accurate it is,
               and prepares the pitch.

  IN ONE SENTENCE:
    Grandma shows it a suspicious message, the AI investigates like a
    detective, gives a clear and kind answer with proof, and protects
    her and her family if something already went wrong.

  It's always kind and never makes her feel stupid.

  Closing line for the pitch:
    "Scammers use AI to sound like your grandson.
     We use AI to protect your grandmother."

// lib/contract.ts

// ---------- Request to the agent ----------
export type Language =
  | "en" | "es" | "fr" | "pt" | "zh" | "hi" | "ar" | "vi" | "ko" | "tl";

export interface AgentRequest {
  text?: string;                 // pasted message text
  images?: InputImage[];         // screenshots (max 4)
  video?: VideoInput;
  language: Language;
  alreadyActed?: boolean;        // user already paid / replied / shared
  actionDetails?: string;        // e.g. "I sent one $500 gift card"
  familyContact?: FamilyContact;
  demo?: boolean;                // replay recorded events, no API calls
}

export interface InputImage {
  mediaType: "image/jpeg" | "image/png" | "image/webp";
  base64: string;                // no "data:" prefix
}

export interface VideoInput {
  blobUrl: string;               // Vercel Blob URL of the original video
  frames: InputImage[];          // 8-12 JPEG frames, max 768px wide
  frameTimes: number[];          // seconds, same order as frames
  durationSec: number;
  fileName: string;
}

export interface FamilyContact {
  name: string;
  phone?: string;                // E.164, e.g. +15551234567
  email?: string;
}

// ---------- Investigation tools (P2 implements, P1 calls) ----------
export interface ExpandLinkResult {
  inputUrl: string;
  finalUrl: string;
  hops: { url: string; status: number }[];
  error?: string;
}
export type ExpandLink = (url: string) => Promise<ExpandLinkResult>;

export interface DomainAgeResult {
  domain: string;
  createdAt: string | null;      // ISO date
  ageDays: number | null;
  registrar?: string;
  isNew: boolean;                // ageDays < 30
  error?: string;
}
export type DomainAge = (domain: string) => Promise<DomainAgeResult>;

export interface LookalikeResult {
  domain: string;
  impersonates: string | null;   // e.g. "usps.com"
  similarity: number;            // 0-1
  technique?: "typo" | "extra_words" | "char_swap" | "subdomain_trick"
            | "tld_swap";
}
export type LookalikeCheck = (domain: string) => Promise<LookalikeResult>;

export interface ReputationResult {
  url: string;
  listedAsMalicious: boolean;
  sources: { name: string; verdict: string }[];
  error?: string;
}
export type CheckReputation = (url: string) => Promise<ReputationResult>;

export interface VideoReport {
  credentials: {
    found: boolean;
    generator?: string;          // from the C2PA manifest
    claims?: string[];
    error?: string;
  };
  metadata: {
    clues: string[];             // plain-English clues from ffprobe
    encoder?: string;
    creationTool?: string;
    hasCameraInfo: boolean;
    error?: string;
  };
  detector: {
    provider: string;
    aiProbability: number;       // 0-1
    error?: string;
  } | null;                      // null = no detector configured
}
export type AnalyzeVideo = (blobUrl: string) => Promise<VideoReport>;

  delivered: boolean;
  channel: "sms" | "email" | "screen";
  error?: string;

  contact: FamilyContact,

// ---------- Verdict ----------
export type VerdictLevel = "scam" | "suspicious" | "safe";
export type AiMediaLevel = "likely_ai" | "unclear" | "likely_real";
export type ScamType =
  | "grandparent" | "delivery" | "bank_impersonation" | "romance"
  | "tech_support" | "government_impersonation" | "prize_lottery"
  | "investment_crypto" | "celebrity_deepfake" | "phishing_other"
  | "none" | "unknown";

  level: VerdictLevel;
  confidence: number;            // 0-1

  reasons: string[];             // 2-3 plain-language reasons

export interface DamageControlPlan {
  steps: { title: string; detail: string; urgent: boolean }[];

    agency: "FTC" | "IC3" | "local_police" | "bank" | "gift_card_company";
    url: string;
    prefilledText: string;
  }[];

// ---------- Live events: server -> browser ----------
// Server-Sent Events. Each event:  data: <JSON AgentEvent>\n\n
// Order: plan -> (step_start -> evidence* -> step_done)* -> verdict
//        -> [family_alert] -> [damage_control] -> done
// "text" can appear anywhere. "done" is ALWAYS sent last, even after errors.
export type AgentEvent =
  | { type: "plan"; steps: string[] }
  | { type: "step_start"; id: string; label: string; tool?: string }
  | { type: "step_done"; id: string; ok: boolean; summary: string }
  | { type: "evidence"; id: string; finding: string;
      severity: "red" | "yellow" | "green" | "info" }
  | { type: "text"; delta: string }
  | { type: "verdict"; verdict: Verdict }
  | { type: "family_alert"; alert: FamilyAlert; result: FamilyAlertResult }
  | { type: "damage_control"; plan: DamageControlPlan }
  | { type: "error"; message: string; recoverable: boolean }
  | { type: "done" };

=====================================================================
  APPENDIX B - CLAUDE API RULES (current; older examples may be wrong)
=====================================================================
  - SDK: @anthropic-ai/sdk. const client = new Anthropic() reads
    ANTHROPIC_API_KEY. Use the SDK types (Anthropic.MessageParam,
    Anthropic.Tool, Anthropic.ToolUseBlock, Anthropic.ToolResultBlockParam).
  - Model: "claude-opus-5-5" (exact, no date suffix).
  - Thinking can't be disabled on this model. Never send
    thinking:{type:"disabled"} or budget_tokens (400 error). You may
    send thinking:{type:"adaptive"}.
  - Effort defaults to "medium". Set output_config:{effort:"high"} for
    the agent and {effort:"low"} for cheap checks.
  - Forced tool use returns a 400: tool_choice {type:"any"} and
    {type:"tool"} are both rejected. Use auto (the default) and say in
    the system prompt which tool to call.
  - Web search (server tool, no client code):
      { type: "web_search_20260209", name: "web_search", max_uses: 6 }
    Don't also add code_execution. Errors come back as a
    web_search_tool_result whose content is an object with error_code
    (success content is an array).
  - Images: { type:"image", source:{ type:"base64",
    media_type:"image/jpeg", data } }. Put images before the text block.
  - Loop: client.messages.stream({...}) then await stream.finalMessage(),
    max_tokens 64000, at most 12 turns. Append the full response.content.
      stop_reason "tool_use"   -> run tools and return ALL tool_result
                                  blocks in ONE user message
      stop_reason "pause_turn" -> append the assistant content and call
                                  again
      stop_reason "end_turn"   -> finished
      "max_tokens" / "refusal" -> don't run that turn's tools; send a
                                  friendly error event
  - Client tools in a streamed request: eager_input_streaming: true, and
    validate every input with zod. Invalid or failed -> tool_result with
    is_error: true (never drop a tool_result).
  - Errors: catch Anthropic.RateLimitError (wait and retry), then
    Anthropic.APIError, then network errors. Show users a calm message.
  - Optional: refusal fallback (Claude API only) via
    client.beta.messages.stream with
    betas:["server-side-fallback-2026-07-01"], fallbacks:"default".
